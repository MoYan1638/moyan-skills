# 代码风格片：20 种全代码生成的视觉风格

画面每一帧都由代码算出来（Canvas / WebGL / 光线步进 3D），不用素材库、不用模板、不用版权音乐。配乐和音效同样由代码合成。

**核心立场**：这类片子的门槛不在"选风格"，而在"**像真实拍摄/顶级工作室作品，看不出是代码做的**"。观众先觉得好看，知道是纯代码才惊讶。做成"一看就是电脑画的平面图层"就白做了。

## 一、20 种风格速查（按"真实世界的物理对应"理解）

选风格时别只看名字，看**它在现实世界里对应什么材质**——这决定了要不要 3D、要多少渲染成本。

| 类别 | 风格 | 现实对应（决定实现路线） | 成本档 |
|---|---|---|---|
| 手绘/平面 | 逐帧手绘 | 纸上铅笔+水彩，线条自然抖动、颜色淡 | 低（Canvas 2D） |
| | 扁平矢量 | 印刷色块，无渐变无阴影 | 低 |
| | 几何构成（包豪斯） | 悬浮的胶合板，只在一个角度拼成海报 | 中（解析求交） |
| 3D/渲染 | 等轴 2.5D | 正交投影的模型玩具，无透视变形 | 中 |
| | 3D 渲染 | 真实光影材质，软阴影 + 环境光遮蔽 | 高（光线步进） |
| | 液态流动 | 金属/液体流动，反射随视角变 | 高 |
| 动画/特效 | 线条动画 | 单笔生长轨迹 | 低 |
| | 形变动画 | 形态平滑过渡（需 morph 工具） | 中 |
| | 赛博朋克 HUD | 发光屏 + 扫描线 + 数据流 | 中（WebGL） |
| 创意/手工 | 贴纸风科普 | 贴纸拼接：白边、投影、微微翘起 | 低~中 |
| | 拼贴剪贴 | 桌上的纸：厚度、撕边白纤维、泡棉垫高的字、胶带、印章油墨 | 高（画进画布再用 WebGL 打光） |
| | 黏土定格 | 手捏的泥：指纹、微抖、微距景深、每秒 12 张 | 高 |
| 复古/艺术 | Synthwave | 80 年代霓虹网格，地平线落日 | 低 |
| | 像素风 | 低分辨率栅格，逐像素 | 低 |
| | 水墨国风 | 宣纸墨晕成山、一笔笔画出、最后盖朱印 | 中 |
| 实用/现代 | 综艺花字 | 动态文字 + 表情符号贴片 | 低 |
| | 真实页面 2.5D 推镜 | 真实网页截图做层，镜头推拉（做产品演示最好用） | 低 |
| | 数据新闻编辑风 | 杂志排版 + 图表，网格严整 | 低 |
| | 玻璃拟态 | 半透明层 + 背景渐变（注意：这是"AI 味"高危风格，见下） | 中 |
| | 蓝图工程图 | 工程图纸线条 + 标注 | 低 |

**成本档的真实含义**：纯 CPU 软件渲染下，平面风格 10 秒约 1~10 分钟，WebGL 5~40 分钟，3D 光影 25~80 分钟。**先渲单帧看效果，再渲整段**，这是唯一能省时间的顺序。

## 二、风格选择决策（问场景，不问偏好）

| 内容类型 | 首选 | 避免 |
|---|---|---|
| 知识科普/教育 | 贴纸风、扁平矢量、逐帧手绘 | 3D 渲染（成本高、信息密度低） |
| 产品演示/UI 展示 | 真实页面 2.5D 推镜、等轴 2.5D | 黏土定格（与产品质感冲突） |
| 品牌形象/发布会 | 液态流动、3D 渲染、几何构成 | 综艺花字（廉价感） |
| 数据/报告/新闻 | 数据新闻编辑风、蓝图工程图 | 手绘类（权威感不足） |
| 儿童/亲子 | 黏土定格、贴纸风 | Synthwave、HUD |
| 国风/文化 | 水墨国风、拼贴剪贴 | 像素风、霓虹 |
| 游戏/怀旧 | 像素风、Synthwave、HUD | 极简扁平（没有情绪） |
| 短视频开场/带货 | 综艺花字 + 2.5D 推镜组合 | 单用 3D（前 3 秒不够抓） |

**一次只用一种主风格**。混搭只在"主风格 + 一段花字/信息卡"这种层级关系下成立，两种视觉语言平权地混会变成 PPT。

## 三、技术契约（写代码时必须守的 6 条）

1. **时间唯一输入**：`render(t)` 只根据 `t` 画这一帧，不依赖上一帧、不依赖真实时钟、不用 `Math.random()` 驱动动画。需要随机用固定种子（`rng(seed)` 或哈希）。否则每次渲染结果不同，无法返工和补帧。
2. **设计坐标 1920×1080**，实际画布分辨率乘以缩放系数。
3. **音效做成事件表**：`cues: [{ t: 0.62, sfx: 'splash', gain: .8 }]`，渲染时导出 cues.json 交给音频合成。**音效时间点是数据不是代码**，改节奏只改这张表。
4. **节拍优先**：120 BPM = 每拍 0.5 秒。10 秒场景要有 1 个"钩子时刻"和清晰节拍，所有动效落在拍点上。
5. **运动模糊用子帧叠加**：每帧渲染 N 个子帧混合。快速运镜 12~24，普通 2~6，定格动画配合 `frameKey`（每秒只算 12 帧）用 2 且关快门。
6. **文字全部走配置**：`Reel.cfg({ title: '...' })`，画面上的字不许硬编码在绘制逻辑里——否则换个文案要改代码。

## 四、真实感对照表（风格片最容易缺的 8 层）

"像真的"不是靠加细节，而是靠下面这些物理线索。按风格取用：

| 层 | 做法 | 适用 |
|---|---|---|
| 面积光软阴影 | 阴影有半影过渡，不是硬边灰块 | 全部 3D / 手工类 |
| 环境光遮蔽 | 缝隙、接触处自然变暗 | 3D、拼贴、黏土 |
| 材质 | 纸纹、清漆反光、金属、玻璃折射 | 拼贴、液态、玻璃 |
| 景深 | 焦点外柔和虚化 | 黏土、微距、3D |
| 运动模糊 | 子帧叠加 | 所有有快速运动的镜头 |
| 镜头感 | 暗角、极轻色散、细颗粒、曝光轻微闪烁 | 全部（尤其"真实拍摄"感） |
| 时间变化的光 | 10 秒内光线色温/角度微变 | 手绘、3D、水墨 |
| 不完美 | 手绘抖线、黏土指纹、纸边纤维、墨的随机洇开 | 手工/艺术类 |

**做 3D 风格的关键取舍**：能解析求交的（平板、球、盒子）就别光线步进。包豪斯那种"薄板"用射线-平板解析求交，速度差一个量级。

## 五、改文案 / 换品牌的标准流程

1. 打开目标风格的 `index.html`，只改顶部 `const C = Reel.cfg({ ... })` 里引号内的字
2. 渲单帧确认排版没溢出、没裁字：`node make.js still 09 6.5`
3. 改调性就调节奏（拍点、钩子时刻），不要靠改配色救
4. 全片出片后抽 6~9 帧拼联系表（contact sheet）复查：穿帮、镜头出界露画布边、文字重叠、署名对不对

## 六、渲染与音频自检（交付前必做）

- **抽帧看三处**：开头、钩子时刻、结尾各一帧，亲眼看
- **联系表复查**：抽 6~9 帧拼一张图整体看，快速运镜处检查有没有两道重影（子帧不够）
- **响度**：`ffmpeg -i out.mp4 -af ebur128=peak=true -f null -`，目标约 **-15 LUFS**，真峰值 **≤ -1 dBTP**
- **平台规格**：竖屏 1080×1920（抖音/视频号）、横屏 1920×1080（B站/YouTube）；码率按平台推荐，音频 AAC 192k

## 七、性能坑（纯 CPU 渲染会卡死的地方）

1. **着色器分支全执行**：软件渲染下每个分支都跑。把昂贵形状（文字距离场）拆成独立循环，循环上限用 uniform 传入别让编译器展开，位置/旋转/包围盒在 JS 里算好再传
2. **着色器编译失败表现为"页面卡死"**（seek 标记一直不出现）：先看 console。JS 里的常量必须在 GLSL 里重新声明
3. **生成纹理的 2D 画布要开 `{ willReadFrequently: true }`**，否则软件渲染慢几十倍
4. **`file://` 下图片会污染画布**，`getImageData` 会抛错；改用 data URL
5. **改一点就整段重渲是最大浪费**：永远先 `still` 单帧

## 八、和「去 AI 味」的冲突提醒

玻璃拟态（弥散渐变玻璃）在 UI 设计里是高危 AI 味风格，但在视频风格片里是**有效的视觉语言**——因为视频只需要 3 秒的观感冲击，不需要用户在上面操作。别把 UI 那套克制标准硬套到风格片上，反过来也别把风格片的"炫"搬进产品界面。判断标准：**这东西是给人看的，还是给人用的。**
