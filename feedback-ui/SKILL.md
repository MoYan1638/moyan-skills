# UI 反馈设计规范（弹出层 + 加载状态）

为界面选择和设计反馈类 UI 时，遵循本规范。核心原则：**用最小的打扰完成必要的信息传达**。分两部分：弹出层管"怎么提示"，加载状态管"等待时给用户看什么"。

## 一、六种类型速查

| 类型 | 打扰度 | 消失方式 | 承载信息 | 典型场景 |
|---|---|---|---|---|
| Tooltip | ★ | 移开即消失 | 一句话辅助说明 | 按钮功能补充（"邀请码（选填）"） |
| Toast | ★ | 2-3秒自动消失 | 操作结果反馈 | "保存成功"、"已删除" |
| Alert | ★★ | 常驻，手动关或自动消失 | 重要但不紧急的信息 | 系统维护通知、同步失败提醒 |
| Popconfirm | ★★★ | 点击外部/确认后消失 | 一个轻量确认 | 高频操作确认（"确定删除吗？"） |
| Drawer | ★★★ | 关闭按钮/ESC | 大量内容，边看边改 | 长表单编辑、列表项详情 |
| Modal | ★★★★★ | 必须选择按钮 | 中等长度，强制回应 | 删除确认、重要操作二次确认 |

**打扰程度排序：Tooltip < Toast < Alert < Popconfirm < Drawer < Modal**

（注意：Modal 是最重的——它完全打断且强制回应；Drawer 虽然面积大但不打断主流程，背景仍可操作，不要按面积判断打扰度。）

## 二、选型判断

按顺序问自己三个问题：

1. **只是传达信息吗？** → Toast（结果反馈）/ Tooltip（悬停说明）/ Alert（重要不紧急的横幅）
2. **需要用户确认一个动作吗？**
   - 高频、后果轻 → Popconfirm（气泡确认，不挪焦点）
   - 低频、后果重且不可逆 → Modal
   - 可逆（能做撤销）→ **不确认**，直接执行 + Toast 带"撤销"按钮
3. **需要用户输入/浏览大量内容吗？**
   - 需要对照原页面（边看边改）→ Drawer
   - 流程彻底切换（支付、下单、注册）→ 新页面
   - 短表单（内容少）→ Modal，宽度三档：400px（简单表单）/ 520px（常规）/ 720px（复杂）

## 三、硬性规则（避坑）

1. **填表类弹窗禁止"点击蒙层关闭"**——误触即丢数据。必须显式关闭，且做草稿自动保存（localStorage 或接口暂存）。
2. **删除操作默认走"撤销"而非"确认"**：
   - 可撤销 → 直接删除 + Toast 撤销入口（如 Gmail 的做法）
   - 不可撤销（如注销账号、清空数据库）→ 才用 Modal，且文案明确后果
3. **按钮文案写动作，不写"是/否"**：
   - ❌ 「是否退票？ [是] [否]」
   - ✅ 「确认退票？ [放弃退票] [确认扣费并退票]」
   - 危险动作按钮用红色/警示色，安全选项放右侧（桌面）或下侧（移动）
4. **Toast 全局同时最多 1 条**，后到的顶掉先到的，不做堆叠队列。
5. **Alert 语义色约定**：黄色 = 提醒，用户可继续操作；红色 = 失败，需要用户介入。
6. **Modal 内不嵌套 Modal**（套娃确认用 Popconfirm 或改流程）。

## 四、移动端差异

- **Modal 不适用**：手机上改用全屏页或半屏 Sheet（Bottom Sheet）
- Drawer 改为从底部滑出的半屏/全屏 Sheet，不支持背景操作
- Popconfirm 变为居中轻量确认框（ActionSheet 仅用于多选项选择，不用于确认）
- Tooltip 几乎不用（无 hover），改为长按提示或首次引导气泡
- 触摸目标 ≥ 44px，弹层内的关闭按钮远离拇指热区防误触

## 五、加载状态怎么选（弹出层配套）

四种主流加载组件，按"能不能拿到真实进度"和"等待区域大小"选：

| 组件 | 适用信号 | 典型位置 | 禁止使用 |
|---|---|---|---|
| Spinner 转圈 | 不知道耗时、局部小区域等待 | 按钮内、下拉刷新、单卡片局部 | 长时间整页等待（无进度易焦虑） |
| Progress 进度条 | 能拿到总量和真实进度回调 | 上传、下载、导出、批量任务 | 接口没有进度回调时（禁止伪造匀速假进度） |
| Skeleton 骨架屏 | 整页/整列表首屏等待，需给布局预期 | 首屏、长列表、商品/文章详情 | 布局未定稿的页面（改版需同步维护） |
| Typing 三点跳动 | "正在生成回复"的对话场景 | AI 聊天气泡、客服对话内 | 通用接口加载（通用性弱） |

**顶部全局进度条**（NProgress 风格）是 Progress 的衍生：路由切换时页面顶部 2px 细条，起步快、中段放缓、完成瞬间冲满后淡出，无精确百分比。

**与弹出层搭配使用：**
- Modal / Popconfirm 的提交按钮 → 按钮内嵌 Spinner，加载时禁用按钮防重复提交
- Drawer 打开并加载远程数据 → 抽屉内容区先上 Skeleton 骨架
- 批量操作弹窗且后端返回进度 → 弹窗内放 Progress 进度条
- Toast 只做结果反馈（成功/失败），**Toast 本身不放加载动画**

**AI 提示词要点（生成加载组件时给出这些约束）：**
- Spinner：环形、线条 2px、淡底色+高亮弧旋转、24px、CSS animation 无限循环；可内嵌按钮；颜色跟随主色、支持深色模式
- Progress：高 4px 圆角、浅灰底+主色填充、绑定真实 progress 0~100、右侧显示百分比、完成后过渡到满条再消失；明确"禁止写死假匀速动画"
- Skeleton：占位结构与真实卡片布局逐块对齐（头像块/标题行/文本行/标签位）、shimmer 扫光从左向右循环、数据到位后平滑替换为真实内容、适配深色模式
- Typing：3 个 6px 圆点、间距 4px、依次上下跳动、气泡内居中、AI 开始输出文字后立即移除

**加载状态避坑：**
1. 不叠加多个 loading（骨架里不再放 Spinner，二选一）
2. 加载中必须锁交互：按钮 Spinner 期间禁用点击
3. 骨架尺寸严格对齐真实 DOM，否则内容替换时布局跳闪
4. 禁止纯定时器匀速涨的假进度（与真实业务脱节，比没有进度更糟）
5. 动画时长柔和克制，不晃眼、不花哨

## 六、快速对照示例

| 场景 | 正确选择 | 错误选择 |
|---|---|---|
| "已复制到剪贴板" | Toast | Modal |
| 输入框旁解释格式 | Tooltip | Alert |
| 批量删除 10 条列表项 | 直接删 + 撤销 Toast | Modal 确认 |
| 注销账号 | Modal（红字写明后果） | Popconfirm |
| 编辑列表中某客户的完整资料 | Drawer | Modal |
| 支付流程 | 新页面 | Modal/Drawer |
| 服务器维护预告 | Alert（顶部横幅） | Modal |
| 表单提交等待接口返回 | 按钮内 Spinner | 整页遮罩 Skeleton |
| 文件上传 | Progress 进度条 | Spinner 转圈 |
| AI 回复生成中 | Typing 三点 | Progress 进度条 |
| App 首页首次进入 | Skeleton 骨架屏 | 居中大 Spinner |
