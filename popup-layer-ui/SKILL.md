# 弹出层设计规范

为界面选择和设计弹出层时，遵循本规范。核心原则：**用最小的打扰完成必要的信息传达**。

## 一、六种类型速查

| 类型 | 打扰度 | 消失方式 | 承载信息 | 典型场景 |
|---|---|---|---|---|
| Tooltip | ★ | 移开即消失 | 一句话辅助说明 | 按钮功能补充（"邀请码（选填）"） |
| Toast | ★ | 2-3秒自动消失 | 操作结果反馈 | "保存成功"、"已删除" |
| Alert | ★★ | 常驻，手动关或自动消失 | 重要但不紧急的信息 | 系统维护通知、同步失败提醒 |
| Popconfirm | ★★★ | 点击外部/确认后消失 | 一个轻量确认 | 高频操作确认（"确定删除吗？"） |
| Drawer | ★★★ | 关闭按钮/ESC | 大量内容，边看边改 | 长表单编辑、列表项详情 |
| Modal | ★★★★★ | 必须选择按钮 | 中等长度，强制回应 | 删除确认、重要操作二次确认 |

**打扰程度排序：Tooltip < Toast < Alert < Popconfirm < Drawer < Modal**

（注意：Modal 是最重的——它完全打断且强制回应；Drawer 虽然面积大但不打断主流程，背景仍可操作，不要按面积判断打扰度。）

## 二、选型判断

按顺序问自己三个问题：

1. **只是传达信息吗？** → Toast（结果反馈）/ Tooltip（悬停说明）/ Alert（重要不紧急的横幅）
2. **需要用户确认一个动作吗？**
   - 高频、后果轻 → Popconfirm（气泡确认，不挪焦点）
   - 低频、后果重且不可逆 → Modal
   - 可逆（能做撤销）→ **不确认**，直接执行 + Toast 带"撤销"按钮
3. **需要用户输入/浏览大量内容吗？**
   - 需要对照原页面（边看边改）→ Drawer
   - 流程彻底切换（支付、下单、注册）→ 新页面
   - 短表单（内容少）→ Modal，宽度三档：400px（简单表单）/ 520px（常规）/ 720px（复杂）

## 三、硬性规则（避坑）

1. **填表类弹窗禁止"点击蒙层关闭"**——误触即丢数据。必须显式关闭，且做草稿自动保存（localStorage 或接口暂存）。
2. **删除操作默认走"撤销"而非"确认"**：
   - 可撤销 → 直接删除 + Toast 撤销入口（如 Gmail 的做法）
   - 不可撤销（如注销账号、清空数据库）→ 才用 Modal，且文案明确后果
3. **按钮文案写动作，不写"是/否"**：
   - ❌ 「是否退票？ [是] [否]」
   - ✅ 「确认退票？ [放弃退票] [确认扣费并退票]」
   - 危险动作按钮用红色/警示色，安全选项放右侧（桌面）或下侧（移动）
4. **Toast 全局同时最多 1 条**，后到的顶掉先到的，不做堆叠队列。
5. **Alert 语义色约定**：黄色 = 提醒，用户可继续操作；红色 = 失败，需要用户介入。
6. **Modal 内不嵌套 Modal**（套娃确认用 Popconfirm 或改流程）。

## 四、移动端差异

- **Modal 不适用**：手机上改用全屏页或半屏 Sheet（Bottom Sheet）
- Drawer 改为从底部滑出的半屏/全屏 Sheet，不支持背景操作
- Popconfirm 变为居中轻量确认框（ActionSheet 仅用于多选项选择，不用于确认）
- Tooltip 几乎不用（无 hover），改为长按提示或首次引导气泡
- 触摸目标 ≥ 44px，弹层内的关闭按钮远离拇指热区防误触

## 五、快速对照示例

| 场景 | 正确选择 | 错误选择 |
|---|---|---|
| "已复制到剪贴板" | Toast | Modal |
| 输入框旁解释格式 | Tooltip | Alert |
| 批量删除 10 条列表项 | 直接删 + 撤销 Toast | Modal 确认 |
| 注销账号 | Modal（红字写明后果） | Popconfirm |
| 编辑列表中某客户的完整资料 | Drawer | Modal |
| 支付流程 | 新页面 | Modal/Drawer |
| 服务器维护预告 | Alert（顶部横幅） | Modal |
