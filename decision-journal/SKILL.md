# 决策日志（decision-journal）

人做决定时逻辑清楚，但记忆只保留结论、不保留理由。两周后只剩"当时定了先上静态版"，却忘了为什么，于是开始怀疑、摇摆、推翻重做。更隐蔽的坑是事后脑补：结果好就觉得"我当时想得周全"，结果坏就觉得"我蠢"——两种都是幻觉。本 skill 给每个重要决定装行车记录仪。

## 触发时机（语义自动识别，不依赖固定口令）

判断依据是**语义**，不是关键词命中。用户不需要说任何特定的话：

1. **留档**：对话中出现"拍板"瞬间即自动触发。典型语义信号：
   - 在多个方案中做出取舍："先做 A""不用 B 了""改走 X 方案""A 和 C 都行，那就 B 吧"
   - 对待办/方向给出终态确认："行，就这么干"" OK 那定了""可以，按这个来"
   - 用户否决某个此前讨论过的路径："时间胶囊先不做了"
2. **回查**：用户想追溯过去决策的语义——"当时为什么不上 AI""这个之前是不是讨论过""我那时预期是什么"——读日志文件，原样调出对应条目，**不加工、不美化**。

触发后的动作：**用一句话问确认**（"这个决定我帮你记条日志？"），用户嫌烦或连续决策场景下，先记再说并告知一句即可，不反复打断对话流。鸡毛蒜皮的小事（硬规则第 1 条筛不过的）不触发、不询问。

## 日志格式

每条 6 个字段，30 秒内可填完：

```
## 📌 决策 #003 | 2026-10-24 | <项目/主题名>
- 决定：<一句话说清选了什么>
- 背景：<当时的环境和约束，1-2 句>
- 备选项：A. xxx　B. xxx　C. xxx
- 理由：<选它而不是别人的核心理由，2-3 句>
- 预期：<写下"我认为会发生什么"和可验证的信号，如"3 个月内 UV 破 1000 则验证走对">
- 关联：<相关决策编号 / 相关项目>
```

## 存储约定

- 文件：`D:\WorkBuddyData\Claw\.workbuddy\memory\decisions.md`
- 新条目追加到文件末尾，编号递增，不删不改旧条目
- 决定本身变了不是改旧条目，而是记一条新条目并注明"推翻 #00X，理由……"

## 硬规则

1. **只记"分岔点"**，不记鸡毛蒜皮。判断标准：如果这个决定做反了，会不会造成返工或方向错误？会→记；不会→不记。
2. **预期字段必填**。没有可验证预期就不是决策日志，是流水账。
3. **记录理由要写"为什么不是 B"**，只写"为什么是 A"等于没写。
4. **回查时保持中立**。调出的是当时的原始判断，用户自己对照结果复盘；不替用户辩护也不落井下石。
5. **复盘联动**：用户使用 retrospective-advisor 复盘时，主动查决策日志——走偏的那步先看"是决定本身错了还是执行走样了"，两种问题解法完全不同。
6. 每记满 20 条，提示用户可做一次决策风格小结（规律性倾向、常见后悔模式），生成后单独存一节。

## 一句话灵魂

记的不是"决定了什么"，是"当时为什么这么定、以及当时赌了什么结果"。
