# button-patterns 高级按钮交互六合一

提供 6 种高频场景下的高级按钮交互实现方案，每个方案附物理参数基准、可直接使用的 AI 提示词、边界情况处理，帮助开发者快速实现具备真实手感和高级感的按钮交互，解决 AI 生成按钮缺乏交互反馈、质感不足、只有两态没有状态机的问题。

**六个方案**：长按确认 · 点赞迸发 · 滑动确认 · 加入购物车飞入 · 主题切换扩散 · 复制反馈

**核心方法：按钮是状态机**——每个按钮强制覆盖"初始 → 操作中 → 完成 → 恢复"四态，每态都有明确视觉（必要时触觉）反馈，两态按钮就是没做完。

**每个方案包含**：交互表现 → **何时不用**（每个方案的明确不适用场景，如长按确认只留给不可逆操作、密集列表点赞用轻量版不炸粒子）→ 物理参数基准（时长/曲线/阈值，验收就核它）→ 可直接使用的 AI 提示词 → 边界情况处理。关键参数已与 ui-patterns 的微交互动效配方对齐（长按 1.5s 按满/松手 350ms 缓退、点赞粒子 8 点均分 34~60px 飞散），二者不冲突。

另附**配套验收提示词**——实现完成后原样发给 AI 让它按五项自查（四态表现/参数对齐/异常处理/无障碍/何时不用），缺项补齐再交付。

**四块公共设施**：
- **场景速选表**——按场景一眼选对方案；选档纪律：一个界面只有 1 个主行动按钮配高级动效，其余统一基础按压反馈，满屏都在动就没有重点
- **平台实现锚点**——Android Compose / iOS SwiftUI / H5 / 小程序四端落地 API 映射（含小程序动效必须走 CSS 避免 setData 卡顿的坑），禁止凭空造 API
- **无障碍硬规则**——非颜色区分完成态、结果反馈读屏播报（aria-live）、触控目标 ≥ 44pt，以及关键一条：**长按确认/滑动确认必须提供等效替代路径**（二次确认弹窗/点击确认），照顾无法完成长按或拖动的用户
- **验收清单**——五个勾选项逐项过：四态齐全、按压 ≤120ms 与三数字对齐、连点/打断状态机不破、无障碍四条、降级路径实测

**核心原则**：物理反馈优先（弹簧/回弹/震动，按压反馈 120ms 内出现，禁生硬线性动画）；全状态覆盖；服务操作不喧宾夺主；可降级（震动/扩散等平台能力不可用静默降级，尊重系统减弱动态效果）。

**输出要求**：每个按钮交付交互说明文档（操作方式/视觉反馈/边界情况）；多端适配 App/小程序/H5，平台原生能力优先，H5 按降级方案处理；一次性动画必须清理节点或复位状态机、支持反复触发。

**与其他 skill 配合**：ui-patterns 的微交互动效章节是速查配方、本 skill 是完整实现方案；motion-patterns 管页面级动效、本 skill 管控件级按钮动效；demo-to-prod 上线验收用。
