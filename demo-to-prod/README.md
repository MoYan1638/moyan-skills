# demo-to-prod 生产硬化

> 🧩 本 skill 是 [MoYan1638/moyan-skills](https://github.com/MoYan1638/moyan-skills) 系列的一员，更多 skill 看那边。

把 AI 生成的"可运行 Demo"转化为"可上线生产级 App"的**五步通用工作流**（适用于电商、社交、工具、内容、企业服务等所有类型）。Demo 和生产代码的差距不在功能，而在**异常路径、并发安全、性能稳定、数据安全**——AI 生成代码最容易糊弄过去的几样。

## 五步工作流（附 30 秒选档）

**先选档再开工**：Lite 档（单人/小工具/无资金无隐私）五步全走但跳过压测与正式审核记录；Full 档（涉资金/隐私/高并发/企业客户）完整无豁免。

1. **定义验收标准** —— 开发前写清可量化、可测试的业务规则，覆盖**核心业务/性能/安全/用户体验**四大维度（操作成功率 ≥99.9%、并发响应达标、隐私全程加密、异常必提示不白屏）；每条编号以便追溯
2. **建立代码约束规则** —— 原子性、幂等、状态机收敛、精度敏感数值禁浮点、参数化查询、权限校验、隐私加密、关键日志，配 ArchUnit/dependency-cruiser/import-linter 自动拦截违规
3. **边写边测真实场景** —— **先过 AI 代码病灶体检表**（吞异常/假幂等/Mock 永真/假装处理并发/密钥硬编码/时区踩坑，命中即打回）再测试：真实数据库 + 并发模拟 + 失败注入 + 性能压测 + 安全测试，核心场景 100% 覆盖；**追溯矩阵**保证每条验收标准都映射到至少一个用例，杜绝假覆盖
4. **人工审核要害** —— 判定标准"出错后需人工善后且成本高"：资金/隐私/核心流程/并发控制/安全防护，人工逐行审
5. **提审预检**（App/小程序必过）—— 平台合规五项：措辞红线扫描（敏感词/AI 功能不得承诺对话式服务）、类目匹配、个人主体功能边界（内购/开放 AI 对话/UGC/站外导流）、游客模式可走通、素材合规；产出 **✅ 可提 / ⚠️ 改完再提 / ❌ 提了也会拒** 三态判定；驳回理由沉淀进规则库越用越准

任一环节不过即终止返回修改；最后产出上线报告，判定 ✅ 可上线 / ⚠️ 整改后上线 / ❌ 禁止上线。

与其他 skill 分工：`enterprise-ai-agent` 管企业级智能体搭建（智能体项目两者串联）、`github-publisher` 管发布动作。
