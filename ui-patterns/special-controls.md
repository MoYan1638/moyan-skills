## 一、徽标（Badge）

**定位规则**：挂在宿主右上角，中心压在圆角边缘上（约压边 50%），带 **2px 与宿主同色的描边**——不然压在深色图标上边界糊掉。

**硬性规则**：

1. **数字封顶 99+**，超过显示 `99+`；**数量为 0 时隐藏数字徽标**（显示"0 条未读"是反模式；需要表达"曾经有过"时用红点）
2. 同一宿主**只放一个徽标**，数字与红点二选一；会员/VIP 这类文字徽标是独立元素，别和数字徽标叠在同一坐标
3. 数字变化时宿主整体不挪位，徽标自身做一次 `scale 1→1.25→1`（150–250ms，回弹曲线）确认变化，不做闪烁
4. 红点徽标直径 ≥ 8px（可点击宿主上热区仍由宿主承担，不单独扩徽标热区）
5. 无障碍：宿主是可交互元素时，`aria-label` 写全状态（`aria-label="消息，3 条未读"`），不能只靠视觉

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 0 条未读还挂着「0」 | 0 时隐藏，或降级为红点 |
| 徽标把图标顶得偏离中心 | 绝对定位压角，宿主不动 |
| 数字徽标 + VIP 标签叠一起 | 两个信息两个位置 |
| 未读数变化整块闪一下 | 徽标单独回弹一次，150–250ms |

**库映射**：Ant Design `Badge`（`count`/`dot`/`overflowCount`）｜Element Plus `el-badge`｜Arco `Badge`｜小程序无内置，自绘（绝对定位 + 同色描边）。

## 二、数字输入框（Number Input）

**交互三件套，缺一不可**：可直接键入、按钮步进、**长按连续加减**。只能点的步进器是负体验——用户要买 30 个就得点 29 下。

**硬性规则**：

1. **长按加速**：按下 380ms 后开始连发，间隔从 90ms 逐步压到 ~30ms；松手立即停（`pointerup/pointerleave/pointercancel` 都要清定时器，手指可能滑出按钮）
2. **边界锁定**：到 min/max 后步进无效；但输入框仍可键入，失焦时钳制回界内——按钮置灰和输入锁定是两件事，别捆死
3. 键入时过滤非法字符（只留数字），失焦回钳制值；`inputmode="numeric"` 唤起数字键盘
4. 键盘 ↑/↓ 步进一格；滚轮步进要 `{ passive: false }` 才能 `preventDefault`，防止页面跟着滚
5. 数值用 `font-variant-numeric: tabular-nums`，步进时数字不左右晃
6. 步进按钮点击区 ≥ 40×40px
7. **何时不用**：值域大且无自然步长（金额）→ 普通输入框 + 校验；模糊选区间 → 双端滑块（主 SKILL 第二部分 #5）

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 只能点按钮，不能键入 | 键入 / 步进 / 长按三通道都在 |
| 长按还是一秒一下 | 380ms 后连发并逐步加速 |
| 到最小值按钮还能点 | 边界锁定 + 输入框仍可键入 |
| 滚轮一滚页面也滚 | `passive:false` 拦截后按格步进 |

**库映射**：Ant Design `InputNumber`｜Element Plus `el-input-number`｜Arco `InputNumber`｜小程序无内置，自绘（注意 `inputmode` 与长按定时器清理）。

## 三、时间轴（Timeline）

**三态视觉，一眼分层**：已完成（实心绿或主题灰）、进行中（强调色实心 + 外圈光晕）、未开始（空心）。连线按状态分段着色，进行中节点到下一节点之间的线用渐变过渡。

**硬性规则**：

1. **进行中节点必须有内容**：写「当前环节 + 时间」，不留空节点悬着
2. 出现**失败/异常态**时是第四种视觉（红色实心 + 图标），不要硬塞进三态里让用户猜
3. 节点 > 7 个时折叠中间的已完成节点（如物流的「已揽收…运输中」合并为一条可展开），首尾节点永远可见
4. 逆向追踪类（物流、订单）用纵向、最新节点在**下**（阅读顺序自上而下 = 时间顺序）；发展历程类展示才用横向
5. 连线画在节点层之下（`z-index` 分层），不能横穿节点圆点
6. 移动端纵向排布，节点文字左对齐，时间戳用次要色小一号

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 五个节点全是灰点 | 三态分明，进行中带光晕 |
| 「运输中」节点下面什么都没写 | 环节名 + 时间 |
| 失败节点和完成节点同色 | 第四态：红色 + 图标 |
| 20 个物流节点全平铺 | 中段折叠，首尾常驻 |

**库映射**：Ant Design `Steps`（流程）/`Timeline`（记录）｜Element Plus `el-timeline`｜Arco `Timeline`｜小程序无内置，自绘（连线用伪元素，注意 `z-index`）。

注意 `Steps` 与 `Timeline` 的分工：**Steps 管流程进度**（用户要做什么，下一步去哪），**Timeline 管事实记录**（发生了什么，何时发生）。物流用 Timeline，注册流程用 Steps，别混。

## 四、翻页器（Pagination）

**硬性规则**：

1. **页数 ≤ 7 全展示**；更多时折叠省略号：`1 … (当前-1) 当前 (当前+1) … 总页数`，首尾页永远常驻
2. 上一页/下一页按钮在边界处**置灰禁用**（透明度 ~0.35），不隐藏——位置稳定
3. 数据刷新（搜索、筛选变化）后**回到第 1 页**；同一筛选下翻页保持状态
4. 点页码后**滚动回列表顶部**，别让用户停在页面中部看新页面的中段
5. 跳页输入框只在页数 > 20 时出现，且校验范围（超界钳制 + 提示）
6. **移动端默认不用翻页器**：列表改「加载更多」或无限滚动；翻页器留给后台表格场景
7. 当前页按钮不可再点；页码用 `tabular-nums` 防抖

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 100 个页码全平铺 | 首尾常驻 + 省略号折叠 |
| 搜索结果变了还停在第 5 页 | 新查询回到第 1 页 |
| 翻页后视口停在列表中部 | 翻页即滚回列表顶部 |
| 手机商品列表用页码 | 加载更多 / 无限滚动 |

**库映射**：Ant Design `Pagination`（`simple` 移动端）｜Element Plus `el-pagination`｜Arco `Pagination`｜小程序自绘或「加载更多」。

## 五、边框流光（Border Beam）

**定位规则**：一道光沿卡片边缘环绕流动，内容本身不动。它是「重点强调」手段——**每屏最多 1–2 个**，铺开用等于没有重点。

**硬性规则**：

1. **光只走边框**：外层容器 `padding:1.5px + overflow:hidden`，内部一层实心背景卡片盖住，光只从 1.5px 的缝里露出来。光扫进内容区是明确反模式
2. 实现：外层放一个超大方块（宽度 170%、`aspect-ratio:1`）居中，`conic-gradient` 透明段 230°+ 亮段，`transform: rotate` 3–4s 线性无限循环；只动 `transform`，交给 GPU
3. **`prefers-reduced-motion: reduce` 时停在一帧**（保留配色、去掉动画），这是无障碍审查必查项
4. 流光卡片内部保持安静：不加粗边框、不加深阴影——流光本身就是重点，内部再强调就互相打架
5. 深浅底分别调光：浅底用饱和主题色（亮度 ~65%），深底可以更亮更细；两套色值，不是一套通吃
6. 循环周期 3–4s；太快像警报，太慢像坏了

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 列表 10 张卡全在流光 | 每屏 1–2 张重点卡 |
| 光扫过文字内容 | 内层实心卡片只露 1.5px 边 |
| 减弱动效模式下照转 | `prefers-reduced-motion` 停一帧 |
| 流光 + 内部再加粗边框阴影 | 内部保持安静 |

**库映射**：各主流库均无内置，自绘。关键坑：不要用 `@property --angle` 动画角度值了事——老浏览器不支持时整道光会消失，大方块旋转法是兼容兜底。

## 六、骨架屏（Skeleton）

选型（用在哪、什么时候不用）见主 [SKILL.md](SKILL.md) 第三部分·加载状态。这里只写实现层增量：

**硬性规则**：

1. **灰块布局严格对齐真实 DOM**：头像位置、行数、每行长度比例都按真内容摆（如标题行 68%、副行 34%），否则替换瞬间布局跳闪——比没有骨架更糟
2. 扫光周期 **1.3–1.5s** 匀速循环，只动 `transform: translateX`；`prefers-reduced-motion` 时保留灰块、停扫光
3. **超过 3–4s 仍是骨架要给兜底**（重试按钮 / 错误态文案）。骨架是「即将有内容」的承诺，不是无限等待的遮羞布
4. 骨架期间锁定该区域交互，不出现「点骨架上的空白处」的怪状态
5. 图片类骨架占位要与图片最终宽高比一致，防止替换时高度跳变

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 骨架三行、真内容五行 | 按真内容布局摆灰块 |
| 骨架里再放一个 Spinner | 二选一（主 SKILL 加载避坑第 1 条） |
| 弱网下骨架转 30 秒 | 3–4s 后给重试兜底 |
| 图片占位是正方形、真图 16:9 | 占位宽高比对齐真图 |

## 七、开关（Switch）

弹性动效配方见主 SKILL 第五部分·果冻开关。这里写状态与行为规则：

**硬性规则**：

1. **改完立即生效，不配确认按钮**；异步场景（要发请求）开关先乐观切换，失败**回弹原状态** + Toast 说明——「点了没反应」和「失败不回弹」是两个都要杜绝的负体验
2. 尺寸基准 46×26px（滑块 20px），触屏热区 ≥ 44px 靠整行 label 包裹实现，不靠开关本体
3. 颜色语义：开 = 主题色，关 = 中性灰；**关不用红色**（红是危险语义，不是「关闭」语义）
4. 高风险开关（如「关闭所有通知」「退出登录」）旁边写一行说明文字，不靠二次弹窗
5. 无障碍：真实 `input[type=checkbox]`，可键盘操作；`:focus-visible` 画外圈；label 整行可点
6. 状态记忆：设置类开关要把结果持久化，刷新后保持；演示态开关才允许刷新归零

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 开关拨了，请求失败没回弹 | 乐观切换 + 失败回弹 + Toast |
| 关 = 红色 | 关 = 中性灰 |
| 只有滑块可点 | 整行 label 可点，热区 ≥44px |
| 设置刷新后还原 | 持久化到本地或服务端 |

## 八、走马灯（Carousel）

**硬性规则**：

1. **自动轮播 4–5s 一张，悬停 / 键盘聚焦即暂停**；用户手动切换（箭头/指示点）后重新计时。`prefers-reduced-motion` 时不自动播，只手动切
2. **指示点可点**，当前页拉长成胶囊（宽 16–18px），别做成不可点的小装饰
3. 左右箭头常驻不隐藏（半透明底 + 模糊即可，hover 加深）；环形循环，最后一张的下一张回到第一张
4. 每张 banner **一句主标 + 一句副标封顶**；整卡是链接热区，不要只在「了解更多」小按钮上
5. 相邻图片预加载：第一屏至少预载第 2 张，防止切换跳白
6. 自动轮播的内容信息量要自足——用户只看 1 秒，靠副标把利益点说完，别依赖「看完整个动画」

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 自动播且不可暂停 | 悬停 / 聚焦暂停，reduced-motion 不自动播 |
| 指示点只是装饰 | 可点 + 当前页胶囊拉长 |
| 切到第 2 张先白屏 1 秒 | 预加载下一张 |
| banner 塞三行小字 | 一句主标 + 一句副标 |

**库映射**：Ant Design `Carousel`｜Element Plus `el-carousel`｜Arco `Carousel`｜小程序 `swiper`（`autoplay` + `circular`，暂停要自己监听 touch 实现）。

## 向 AI 描述八件套，一次说清「控件名 + 位置 + 边界」

示例：*订单卡右上角挂未读徽标，99+ 封顶，数量变化时徽标单独回弹一次；购买数量用数字输入框，可键入可步进，长按加速，范围 1–99；会员卡用边框流光，只走边框 1.5px，周期 3.4s，减弱动效时停一帧。*

**生成后自查清单**：0 值徽标是否隐藏 → 步进器能否键入和长按 → 时间轴进行中节点有无内容 → 翻页后是否滚回列表顶 → 流光是否只走边框且每屏 ≤2 个 → 骨架灰块是否对齐真布局 → 异步开关失败是否回弹 → 走马灯悬停是否暂停。
