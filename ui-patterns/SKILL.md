# 界面设计规范（导航 · 表单 · 反馈 · 质感 · 微互动 · 效果库）

拿到一个页面/界面设计需求时，按这张总图定位要查的部分：

```
拿到页面需求
├─ 页面之间怎么跳转、功能入口怎么摆？      → 第一部分：导航
├─ 用户要往里填东西（输入/选择/上传）？     → 第二部分：表单
├─ 系统要告诉用户什么（提示/确认/等待）？   → 第三部分：反馈
└─ 结构对了但看着廉价、不丝滑？            → 第四部分：质感细节 / 第五部分：微交互动效 / 第六部分：效果决策与提示词库
```

前三者经常同时用：一个设置页 = 侧边栏导航 + 表单输入 + 提交反馈。各自的核心原则：导航**位置稳定**、表单**规则前置**、反馈**最小打扰**、质感**抠视觉与操作的细节**。三条贯穿全篇的基线原则：**层级**（最重要的内容最醒目）、**和谐**（界面配合设备形态保持视觉统一）、**一致**（同样的操作在哪些页面都一个样）。

需要给页面加「背景特效 / 悬停效果 / 滚动效果」这类单点视觉彩蛋时，走下面的**效果决策流程**，然后查 [effects-prompts.md](effects-prompts.md)——18 个效果的 AI 提示词 + 实现要点 + 选型规则。

## 效果决策流程（当用户说「加点效果 / 高级一点 / 炫酷一点」时）

**不要直接把 18 个效果全堆上去，按这个顺序走：**

1. **先问场景，不问效果**：这是首页 / 产品页 / 作品集 / 落地页 / 工具后台？主色调是深色还是浅色？目标用户是 C 端（可炫）还是 B 端（克制）？
2. **自己定方向，给用户选择题而不是开放题**：按场景从决策表挑 2~3 个候选效果，用一句话描述每个的观感差异，让用户选（或说「都按你推荐的来」）。
3. **选完再确认两个约束**：移动端要不要同等效果（决定 hover 类是否退化）、动效幅度要「吸睛」还是「若有若无」。
4. **再动手**：按 effects-prompts.md 对应条目的实现要点写代码，写完用第 4 条选型规则自查。

**场景 → 推荐效果决策表：**

| 场景 | 首选 | 备选 | 避免 |
|---|---|---|---|
| 科技/极客首页（深色） | 粒子连线背景 | 鼠标跟随光晕、流动渐变文字 | 极光渐变（颜色容易脏） |
| 产品/品牌落地页 | 极光渐变背景 | 数字滚动统计、无缝 Logo 墙 | 粒子连线（显得太技术） |
| 作品集/个人站 | 3D 翻转卡片 | 打字机文字、图片悬停放大 | 水波纹按钮（太工具感） |
| 改版/优化展示 | 图片对比滑块 | 滚动堆叠卡片 | — |
| 长文/博客页 | 阅读进度条 | 滚动隐藏导航栏、文字悬浮弹窗 | 背景特效类（干扰阅读） |
| 转化页（注册/购买） | 磁吸按钮 | 流光边框按钮（只给主 CTA） | 粒子连线（分散注意力） |
| 工具/后台页 | 毛玻璃导航栏 | 数字滚动统计 | 除毛玻璃外全避免，后台要克制 |

拿不准时默认推荐**毛玻璃导航栏 + 一个主视觉效果**——这是任何场景都不会错的保底组合。

# 第一部分：导航（侧边栏 / 菜单）

核心原则：**不删功能也能变清爽——先分主次、再分组，而不是先砍入口**。入口位置必须稳定，用户是靠位置记忆找功能的。

## 一、诊断：杂乱侧边栏的病根

动手改之前先判断是哪种病：

1. **没有层级**（入口全一样平铺）→ 分组 + 分主次（本部分方案）
2. **命名不清**（"管理中枢"看不出是什么）→ 改文案，不是改布局
3. **顺序错**（高频入口埋在后面）→ 重排，常用组放最上
4. **平台用错**（手机上硬塞侧边栏）→ 移动端改用底部 Tab + 抽屉

## 二、优化四步（按顺序做）

1. **分组归类**：按使用场景分组（"常用 / 项目 / 内容"），组内加小标题，组间拉开间距，大块区域用淡分割线
2. **突出选中态**：当前入口加深色底块（可加左侧指示条），其他入口文字适当变暗——**变暗但保持可读**，不能糊掉
3. **底部固定低频入口**：设置、帮助、账户固定在侧边栏底部；**升级/会员这类收入入口也放底部显眼位置，不隐藏**
4. **滚动与固定结合**：入口仍多时，"顶部（Logo/搜索）+ 底部（设置/账户）固定，中间滚动"，固定的部分永不参与滚动

## 三、折叠组（入口 30+ 时）

平铺分组装不下时用折叠组（Collapsible Group）：

- 默认折叠，仅展开"常用"组；用户手动展开的组**记住状态**（localStorage），下次保持
- 折叠组标题右侧配箭头并标注子项数；搜索入口常驻顶部，作为折叠的逃生门——找不到就搜，别逼用户逐组展开
- 当前选中项所在组**自动展开**，其他组不动

## 四、选中高亮动效（组内滑动，跨组淡入）

高亮块切换菜单项时，常见缺陷是"滑得太远"：从「今天」切到「设置」，高亮滑过 5 个无关项，视线被拖着走。规则：

- **同一分组内**切换：高亮滑动（View Transitions 滑动动画）
- **跨分组**切换：淡入淡出（旧位置消失、新位置出现，不横穿屏幕）
- 实现只需 CSS 的 `view-transition-name`：同名元素触发滑动，异名触发淡入淡出。**每个分组用不同的 name**：

```css
/* ❌ 所有分组共用一个 name → 跨组也会一路滑过去 */
#workspace .pill { view-transition-name: pill; }
#projects  .pill { view-transition-name: pill; }

/* ✅ 按分组命名 → 组内滑动、跨组淡入淡出 */
#workspace .pill { view-transition-name: pill-workspace; }
#projects  .pill { view-transition-name: pill-projects; }
```

纯 CSS 零 JS。可复用的提示词/AGENTS.md 规则块（写成短条目，别写长解释）：

```markdown
## 动效
- 界面反馈动效使用 150-250 毫秒。
- 选中高亮仅在同一分组内滑动，跨分组时淡入淡出。
```

## 五、坏 ↔ 好对照表

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 22 个入口全一样平排 | 分组 + 小标题 + 组间距 |
| 选中态只靠文字加粗 | 深色底块 + 左侧指示条 |
| 非选中项变暗到看不清 | 变暗但保持可读（对比度 ≥ 4.5:1） |
| 升级入口藏进折叠组里 | 底部显眼位置保留 |
| 改版打乱入口位置 | 位置稳定，新增入口追加不重排 |
| 入口多就砍功能 | 先分组，30+ 再折叠，不删入口 |
| 手机上照搬桌面侧边栏 | 底部 Tab（≤5 个）+ "更多"抽屉 |

## 六、库映射

| 需求 | Ant Design | Element Plus | Arco | 小程序 |
|---|---|---|---|---|
| 分组菜单 | Menu items 里 `type: 'group'` | el-menu-item-group | Menu ItemGroup | 无内置，自绘 |
| 折叠组 | Menu 内嵌 SubMenu | el-sub-menu | SubMenu | 无内置，自绘 |
| 底部固定 | 布局层实现（flex，尾部不滚动） | 同左 | 同左 | 自定义 tabBar |

# 第二部分：表单（输入 + 校验）

核心原则：**在用户犯错之前就告诉 ta 规则，而不是等 ta 犯错之后才报错**。

## 一、13 种组件速查

| # | 组件 | 一句话定义 | 适用场景 |
|---|---|---|---|
| 1 | 浮动标签 | 未输入时标签在框内，聚焦/有内容后缩小移到框上方常驻 | 所有需要明确字段名的输入（手机号、姓名、身份证号） |
| 2 | 验证码输入框 | 6 个独立方格，输入自动跳格、删除回退、支持整段粘贴和短信自动读取 | 短信/邮箱验证码 |
| 3 | 拖拽上传 | 虚线框，拖拽+点击均可；逐文件进度条与删除；框内预先写明类型/大小限制 | 图片、文档上传 |
| 4 | 日期选择器 | 近期日期用日历（支持范围选择）；久远日期（生日）用年/月/日三列滚动 | 订酒店、约时间 vs 出生日期 |
| 5 | 滑块 | 单滑块选单值；双端滑块选区间；精确值滑块旁配输入框双向同步 | 价格区间、距离、年龄、身高 |
| 6 | 自动补全 | 输入时实时列出匹配项并高亮匹配文字 | 选项多且需搜索（城市、学校、国家） |
| 7 | 级联选择 | 选完一级，旁边展开下一级 | 省市区、多级分类 |
| 8 | 标签输入 | 回车生成标签，每个带删除按钮 | 兴趣、技能、关键词等多值字段 |
| 9 | 密码框 | 下方强度条（红→绿），右侧眼睛图标切换明文 | 密码设置/登录 |
| 10 | 下拉选择 | <5 个选项用单选框平铺；≥5 用下拉；需搜索转自动补全 | 单选字段，按选项数量选形态 |
| 11 | 校验报错 | 失焦后校验（不边输边报）；错误提示在框正下方，写清修改方式 | 所有需校验的字段 |
| 12 | 帮助文字 | 框下方常驻灰色说明，输入时不消失 | 有明确填写规则的字段 |
| 13 | 必填星号 | 多数必填→必填项加红星；多数选填→只标"选填" | 必填/选填标识 |

## 二、选型判断

1. **字段值怎么来？**
   - 用户手打 → 输入框（+ 浮动标签）
   - 从固定选项里选 → 按 #10 的数量决策：`<5 平铺单选 / 5+ 下拉 / 选项多需搜索 → 自动补全`
   - 选项有层级 → 级联选择（#7），不要把几百个选项塞进一个下拉
   - 多个自由值 → 标签输入（#8），别让用户手动敲逗号
2. **值是日期吗？** 按时间跨度切：近期 → 日历（范围场景支持入住/离店双选）；久远（生日）→ 三列滚轮。全部用日历翻页翻生日是常见反模式。
3. **值是数值/区间吗？** 模糊选择用滑块，需要精确值就在滑块旁配输入框并双向同步。
4. **是多值/文件吗？** 文件 → 拖拽上传（#3），限制提前写在框内。

## 三、常见 UI 库组件映射

| 本规范 | Ant Design | Element Plus | Arco | 微信小程序 |
|---|---|---|---|---|
| 浮动标签 #1 | Input 无内置，用 Form.Item label 或浮动标签方案 | 同左（社区方案） | 同左 | 无内置，自绘 |
| 验证码 #2 | 无内置，Input + 分格逻辑（社区 otp-input） | 同左 | 同左 | 自绘 + `focus` 控制 |
| 拖拽上传 #3 | Upload.Dragger | el-upload（drag） | Upload(drag) | `chooseMedia` / 自绘 |
| 日期（近期） #4 | DatePicker / RangePicker | el-date-picker | DatePicker | picker mode=date |
| 日期（久远） #4 | 用 DatePicker picker="year" 自组，或自绘三列 | 同左 | 同左 | picker mode=date（多列 selector） |
| 滑块 #5 | Slider（range） | el-slider | Slider | slider 组件 |
| 自动补全 #6 | AutoComplete | el-autocomplete | AutoComplete | 无内置，自绘 |
| 级联 #7 | Cascader | el-cascader | Cascader | 多列 picker |
| 标签输入 #8 | Select mode="tags" | el-select（multiple + allow-create） | TagInput | 自绘 |
| 下拉 #10 | Select / Radio.Group | el-select / el-radio | Select / Radio | picker |

注意：多数库的**久远日期选择是弱项**（日历翻几十年），生日字段基本都要自绘三列滚轮，别硬套库组件。

## 四、错误与帮助文字的位置规则

输入框正下方只有**一条槽位**，优先级：`错误提示 > 常驻帮助文字`（不要叠两行把表单撑乱）：

- 无错时：显示帮助文字（灰色）
- 报错时：同一位置替换为错误文案（红色 + 图标），帮助文字隐藏；错误修正后自动换回
- 若帮助规则在报错时仍必要，把规则并入错误文案（如「密码 8-20 位，当前只输入了 5 位」），而不是保留两行
- 相邻两个字段同时报错时，焦点落在**第一个**出错字段，不要只弹一个顶部汇总

## 五、硬性规则（避坑）

1. **不要只用 Placeholder 当字段名**——用户一开始输就看不见了。用浮动标签（#1）或常驻标签。
2. **校验时机 = 失焦后**，不要边输入边报错（用户还没输完就被骂）；也不要只在提交时才报（错误离输入框太远）。
3. **报错要写修改方式，不写"格式错误"**：
   - ❌ 「格式错误」
   - ✅ 「手机号要 11 位，目前输入了 8 位」
   - 位置：输入框正下方，红色，带图标。
4. **限制提前说**：上传的类型/大小、密码的长度规则，都放在框下方常驻帮助文字（#12）或上传框内，不要等用户传完/输完才弹错。
5. **红星克制**：满屏红星 = 没有重点。多数必填时标必填，多数选填时反过来只标选填（#13）。
6. **验证码必须处理两件事**：整段粘贴自动分格进 6 格；支持短信验证码自动读取（iOS one-time-code / Android SMS retriever）。做不到自动分格的方格输入是负体验。
7. **密码框三件套**：强度条 + 眼睛切换 + 失焦才触发强度校验。登录框不要显示强度条。
8. **提交按钮不要轻易置灰禁用**：置灰 + 不解释原因 = 用户不知道还差什么。允许点击、点击后滚动到第一个出错字段并报错；只有单字段小表单（登录）才适合置灰策略。提交中的按钮加载态详见第三部分·加载状态的 Button Loading。
9. **无障碍底线**：每个输入框有真实 `<label for>`（浮动标签也必须绑 label）；报错用 `aria-invalid` + `aria-describedby` 指向错误文案；错误不只靠红色区分（红绿色盲），必须带图标/文字。

## 六、坏 ↔ 好对照表

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| 生日用日历组件，用户翻 40 年 | 年/月/日三列滚轮 |
| 上传 20M 文件后弹「超过 10M」 | 上传框内预先写「≤10M，支持 jpg/png」 |
| 边输入边报「手机号格式错误」 | 失焦后校验 |
| 验证码粘贴「123456」全进第一格 | 自动分格进 6 格，最后一格填完自动提交 |
| 提交后所有错误汇总弹在页面顶部 Toast | 错误在字段正下方 + 滚动定位到第一处 |
| 满屏红星 | 多数选填时只标「选填」 |
| 滑块选年龄，无法精确输入 27 | 滑块 + 输入框双向同步 |
| 城市下拉 300 项滚动找 | 自动补全 + 高亮匹配文字 |

# 第三部分：反馈（弹出层 + 加载状态）

核心原则：**用最小的打扰完成必要的信息传达**。弹出层管"怎么提示"，加载状态管"等待时给用户看什么"。

## 一、七种弹出层速查

| 类型 | 打扰度 | 消失方式 | 承载信息 | 典型场景 |
|---|---|---|---|---|
| Tooltip | ★ | 移开即消失 | 一句话辅助说明 | 按钮功能补充（"邀请码（选填）"） |
| Hover Card | ★ | 移开延迟关闭 | 中等预览信息，可交互 | 用户名/头像悬停出资料预览卡 |
| Toast | ★ | 2-3秒自动消失 | 操作结果反馈 | "保存成功"、"已删除" |
| Alert | ★★ | 常驻，手动关或自动消失 | 重要但不紧急的信息 | 系统维护通知、同步失败提醒 |
| Popconfirm | ★★★ | 点击外部/确认后消失 | 一个轻量确认 | 高频操作确认（"确定删除吗？"） |
| Drawer | ★★★ | 关闭按钮/ESC | 大量内容，边看边改 | 长表单编辑、列表项详情 |
| Modal | ★★★★★ | 必须选择按钮 | 中等长度，强制回应 | 删除确认、重要操作二次确认 |

**打扰程度排序：Tooltip/Hover Card < Toast < Alert < Popconfirm < Drawer < Modal**

（注意：Modal 是最重的——它完全打断且强制回应；Drawer 虽然面积大但不打断主流程，背景仍可操作，不要按面积判断打扰度。）

## 二、弹出层选型判断

按顺序问自己三个问题：

1. **只是传达信息吗？** → Toast（结果反馈）/ Tooltip（悬停说明）/ Alert（重要不紧急的横幅）
2. **需要用户确认一个动作吗？**
   - 高频、后果轻 → Popconfirm（气泡确认，不挪焦点）
   - 低频、后果重且不可逆 → Modal
   - 可逆（能做撤销）→ **不确认**，直接执行 + Toast 带"撤销"按钮
3. **需要用户输入/浏览大量内容吗？**
   - 需要对照原页面（边看边改）→ Drawer
   - 流程彻底切换（支付、下单、注册）→ 新页面
   - 短表单（内容少）→ Modal，宽度三档：400px（简单表单）/ 520px（常规）/ 720px（复杂）

## 三、弹出层硬性规则（避坑）

1. **填表类弹窗禁止"点击蒙层关闭"**——误触即丢数据。必须显式关闭，且做草稿自动保存（localStorage 或接口暂存）。
2. **删除操作默认走"撤销"而非"确认"**：
   - 可撤销 → 直接删除 + Toast 撤销入口（如 Gmail 的做法）
   - 不可撤销（如注销账号、清空数据库）→ 才用 Modal，且文案明确后果
3. **按钮文案写动作，不写"是/否"**：
   - ❌ 「是否退票？ [是] [否]」
   - ✅ 「确认退票？ [放弃退票] [确认扣费并退票]」
   - 危险动作按钮用红色/警示色，安全选项放右侧（桌面）或下侧（移动）
4. **Toast 全局同时最多 1 条**，后到的顶掉先到的，不做堆叠队列。
5. **Alert 语义色约定**：黄色 = 提醒，用户可继续操作；红色 = 失败，需要用户介入。
6. **Modal 内不嵌套 Modal**（套娃确认用 Popconfirm 或改流程）。
7. **悬停类浮层延迟关闭**：Hover Card / Tooltip 移入立即显示，移出等 **100–300ms** 再关——鼠标难免滑出再滑回，瞬间消失会丢操作机会；悬停卡内含可点内容（头像/按钮）时，鼠标移入卡片内不得关闭。

## 三点五、新手引导（漫游式引导）

首次使用时逐步高亮关键功能 + 配操作说明，适合功能较多的应用。边界：
- **只在首次出现**，完成后不再重演（记录状态），可随时跳过
- 一次不超过 3–5 步，只讲核心路径，不是功能全览
- 与空状态/示例数据互补：能靠界面自解释的就不引导

## 四、加载状态怎么选

七种主流加载组件，按"等待发生在哪一层"和"能不能拿到真实进度"选：

| 组件 | 适用信号 | 典型位置 | 禁止使用 |
|---|---|---|---|
| Spinner 转圈 | 不知道耗时、局部小区域等待 | 下拉刷新、单卡片局部 | 长时间整页等待（无进度易焦虑） |
| Button Loading 按钮加载 | 点击后的提交/生成/保存，防止重复点击 | 按钮文字变「提交中」+ 小转圈，完成后恢复可点击 | 纯浏览跳转类按钮 |
| Progress 进度条 | 能拿到总量和真实进度回调 | 上传、下载、导出、批量任务 | 接口没有进度回调时（禁止伪造匀速假进度） |
| Circular 环形进度 | 进度可量化但空间紧凑 | 仪表盘、小型状态卡片 | 需要展示多项并列进度时 |
| Skeleton 骨架屏 | 整页/整列表首屏等待，需给布局预期 | 首屏、长列表、商品/文章详情 | 布局未定稿的页面（改版需同步维护） |
| Page Loader 页面加载 | 首次打开、核心内容未就绪的全页覆盖 | 网站首页、App 启动页 | 返回/Tab 切换时重放（会变成打断）；可快速渲染的页面 |
| Typing 三点跳动 | "正在生成回复"的对话场景 | AI 聊天气泡、客服对话内 | 通用接口加载（通用性弱） |

**顶部全局进度条**（NProgress 风格）是 Progress 的衍生：路由切换时页面顶部 2px 细条，起步快、中段放缓、完成瞬间冲满后淡出，无精确百分比。

**向 AI 描述加载动效，一次给齐三要素**（只说"做个加载动画"必然得到居中转圈）：
1. **动效名称**：Spinner / Button Loading / Progress / Skeleton / Page Loader，具体到类型
2. **等待时长性质**：未知时长（用 Spinner/骨架）、可量化百分比（用 Progress）、页面级首次等待（用 Page Loader/骨架）
3. **使用位置**：按钮内、卡片局部、内容区，还是整页覆盖

示例：*表单提交按钮用 Button Loading，文字变「提交中」加小转圈，完成后变「已提交」恢复可点；上传文件区用真实进度 Progress 条。*

**与弹出层搭配使用：**
- Modal / Popconfirm 的提交按钮 → 按钮内嵌 Spinner，加载时禁用按钮防重复提交
- Drawer 打开并加载远程数据 → 抽屉内容区先上 Skeleton 骨架
- 批量操作弹窗且后端返回进度 → 弹窗内放 Progress 进度条
- Toast 只做结果反馈（成功/失败），**Toast 本身不放加载动画**

**加载状态避坑：**
1. 不叠加多个 loading（骨架里不再放 Spinner，二选一）
2. 加载中必须锁交互：按钮 Spinner 期间禁用点击
3. 骨架尺寸严格对齐真实 DOM，否则内容替换时布局跳闪
4. 禁止纯定时器匀速涨的假进度（与真实业务脱节，比没有进度更糟）
5. 动画时长柔和克制，不晃眼、不花哨
6. 界面反馈动效统一 **150–250ms**

### 加载动效参数（骨架 / 进度 / 图片出场）

选型之外，三个动效的"配方"直接抄：

**骨架屏扫光**：骨架不止是灰块——按真实内容布局摆位后，盖一层半透明光带从左往右匀速平移循环。提示词：*先按真内容的样子摆出灰色占位块，再在整个骨架上盖一层半透明的光，从左往右匀速平移扫过、一直重复；只动位移（transform），交给显卡。*

**平滑进度条**：每拿到一次真实进度，把填充条 transition 到对应位置，中间补平；挪动途中来了新进度，就从此刻位置接着挪。禁止匀速假条——宁可有 3 秒不动也不要与真实进度无关的匀速。提示词：*每拿到一次真实进度就把填充条位移到对应位置，中间用过渡补平，正在挪时来了新进度就从此刻接着挪；不造假进度。*

**模糊到清晰**（图片加载完成后）：不要直接弹出，从模糊 + 半透明起步同步恢复，比纯淡入柔和。提示词：*元素从模糊加透明开始，模糊程度和透明度一起回到正常；时长 700ms，起始模糊 14px。*

**组合时序**：先扫光骨架屏占位 → 数据到、骨架换真内容 → 上传/发布类走真实进度条 → 图片模糊到清晰。同样是等待，预期感完全不同。

## 五、快速对照示例

| 场景 | 正确选择 | 错误选择 |
|---|---|---|
| "已复制到剪贴板" | Toast | Modal |
| 输入框旁解释格式 | Tooltip | Alert |
| 批量删除 10 条列表项 | 直接删 + 撤销 Toast | Modal 确认 |

# 第四部分：质感细节（视觉与交互打磨）

前三部分解决"结构对不对"，这部分解决"看着廉价"——廉价感的本质是没考虑视觉习惯和操作细节。所有参数可直接写进提示词。

## 一、视觉层：不用黑粗边框

| 规则 | 做法 | 参数 |
|---|---|---|
| 层次靠色阶不靠边框 | 相邻层背景色只差一点点，靠整体氛围拉开层次，不用 1px 边框硬切 | 每层背景亮度差 **1%–3%** |
| 输入框聚焦 | 不用突兀亮线，用加深的柔和外圈做出咬合感 | 双环阴影（外环淡、内环深），无亮色描边 |
| 暗色模式字重 | 黑底白字有光晕效应，视觉比实际粗，整体降一档字重让明暗两版粗细一致 | 暗色模式全站字重 **降一档**（如 400→300） |
| 圆角同心 | 嵌套圆角内外不一样大，否则拐角处的缝一头宽一头窄 | 外圈圆角 = 里圈圆角 + 中间缝隙宽度（跑道原理） |
| 框只套一层 | 视线最多穿过一层框：框里的按钮不画边框，悬停变底色即可 | 选中态线条画在格子**内部**，不撑大格子防抖动 |
| 高清屏细线 | 隔行像素减半，细得像发丝丝 | 1px 线在 2x 屏用 **0.5px** |

## 二、文字与排版：三行 CSS 治乱抖

```css
.tabular { font-variant-numeric: tabular-nums; } /* 数字等宽，跳动时不再左右晃 */
.expand  { display: grid; grid-template-rows: 0fr; transition: grid-template-rows .3s; }
.expand.open { grid-template-rows: 1fr; }        /* 0fr→1fr 自适应撑开高度，不用 JS 算高度 */
p { text-wrap: pretty; }                          /* 避免最后一个单字孤零零掉到第二行 */
```

**流式打字（AI 生成文本场景）**：不要生硬蹦字。每个字先带极速高斯模糊再瞬间对焦清晰，相邻字错开依次晕开，视觉上连成温柔的波浪；行内小图标往下挪，让图标中心和文字基线对齐。提示词：*逐字出现时每个字从轻微模糊加透明瞬间对焦清晰，相邻字错开 30ms 依次晕开；行内图标下移 1/8 字高对齐文字中心。*

## 三、AI 对话特有细节

**输入法（IME）回车拦截**：中文输入时回车是选字不是发送。候选框开着时回车只选字；选完字半秒内的回车也拦住（防止输入法多派发一次回车导致误发）。提示词：*检测输入法候选框状态，候选中回车只用于选字；选字后 500ms 内的回车也忽略，不触发发送。*

**滚动跟随策略**（流式输出时不和用户抢滚轮）：
- 滚动条距底部 ≤ 1 行时才自动跟随新输出；用户一动滚轮**立即停止跟随**
- 向上翻超过 3 行出现「跳至最新」悬浮按钮

**分屏拖动防翻车**：
- 拖动分割条时给预览侧盖一层透明遮罩（防鼠标划过 iframe/画布时卡住）
- 按 Esc 立刻弹回原位；双击分割条回到五五对半
- 拖过 80% 时另一侧自动收起，把空间全让出来

## 四、动效分性格 + 彩蛋

**动效按场景分性格，不要全用一个曲线**：
- 拖拽吸附：雷厉风行，零延迟瞬间咬死，**不回弹**
- 点赞反馈：欢快 Q 弹，带一点点回弹
- 复制成功的小对勾：显示 2.5 秒后自动隐身，不占空间

**长文件名省略**：省略号放在**后缀前面**而不是末尾（`项目方案终稿…pptx`），一眼能看到文件格式。

# 第五部分：微交互动效（按钮级）

按钮/开关等小组件的状态反馈动画。四件套配方 + 一个完整可运行示例（`examples/buttons-demo.html`，纯 HTML/CSS/JS 零依赖）。

## 一、四种模式选型

| 模式 | 适用场景 | 时长 | 曲线 |
|---|---|---|---|
| 点赞爆粒子 | 高频正反馈（点赞/收藏），确认感要欢快 | ≈600ms | 回弹 `cubic-bezier(.34,1.56,.64,1)` |
| 提交三连变 | 异步提交，防重复点击且要交代结果 | 300ms 收缩 + 异步等待 + 400ms 对勾 + 1s 复原 | ease-in-out |
| 果冻开关 | 开关切换，要"物理感" | ≈350ms | 弹簧（回弹曲线） |
| 长按确认 | 危险/不可逆操作，用操作成本替代弹窗确认 | 1.5s 按满 | 线性进度 + 松手 350ms 倒退 |

## 二、配方（可直接抄）

**点赞爆粒子**：图标 `scale 1 → 0.8（25%处） → 1.25（60%处） → 1`，同步变红加发光；8 个彩色小圆点以图标中心为圆心按 `2π/8` 均分角度（各加随机抖动）向外飞 34–60px、缩到 0.3 并淡出，动画结束 `onfinish` 移除节点；数字克隆节点做 `translateY(12px)→0` 上滚。**粒子只在激活时炸**，取消点赞不炸。

**提交三连变**：按钮 `width/min-width` 过渡到 48px、`border-radius` 过渡到 50%，文字 `opacity→0`；加载环用 `border + border-top-color` 旋转；成功态换绿色渐变背景，对勾用 SVG `stroke-dasharray/dashoffset` 画线动画；复原前要把对勾的 `animation` 置 `none` 并强制 reflow（`void el.offsetWidth`），否则二次播放不触发。全程加 `busy` 锁防连点。

**果冻开关**：滑块先 `width 32→44px、border-radius 胶囊化`（拉伸相，≈180ms），90ms 后切目标位置（`left` 用回弹曲线过渡），到位后收回复原。底色同步灰→绿 + 发光。

**长按确认**：SVG 圆环 `rotate(-90deg)`，`stroke-dasharray = 周长`，`requestAnimationFrame` 里按 `已过时间/1500ms` 算 `dashoffset`；松手从当前值 350ms 缓退归零（不是瞬间清零）；走满后 shake 动画（左右位移关键帧）→ 变绿换对勾；自动复位前要**重新获取 DOM 引用**（因为 innerHTML 被替换）。`mousedown/touchstart` 启动、`window` 级 `mouseup/touchend` 终止（手指可能滑出按钮）、`mouseleave` 也终止。

## 三、硬性规则

1. 时长按上面表格走，界面级反馈别超过 600ms；进度环倒退要缓退，瞬间归零显得"卡了"
2. 所有一次性动画结束必须清理节点（粒子）或复位状态机（长按），支持反复触发
3. `animation` 重播前先置 `none` + 强制 reflow
4. 触发后加 busy 锁，动画期间忽略重复点击
5. 对勾/图标用 SVG stroke-dashoffset 画线，不要贴图片；触屏与鼠标事件都要绑

完整可运行示例：`examples/buttons-demo.html`（深色玻璃卡片风，含四种模式全部参数）。

# 移动端差异（各部分通用）

## 硬性数字基线（先满足这些再谈别的）

| 项目 | 底线值 | 说明 |
|---|---|---|
| 点击区域 | ≥ 44pt × 44pt | 手指能轻松点到，视觉可以小但热区不能小 |
| 正文对比度 | ≥ 4.5 : 1 | 大字号标题可放宽到 3:1 |
| 动态字号 | 必须支持 | 用户调大系统字号时布局不塌 |
| 深色模式 | 必须支持 | 配色用语义变量，不硬编码色值 |
| 留白与对齐 | 优先于装饰 | 拿不准时加留白，不加装饰元素 |
| 原生组件 | 优先复用 | 能用系统/组件库现成控件就不自定义，一致性和无障碍白送 |

**生成后自查清单**（AI 产出的页面按这四项过一遍再交付）：层级是否突出核心信息 → 点击区是否够大 → 正文对比度是否达标 → 深色模式/大字号下是否正常。

## 平台差异要点

- **导航**：侧边栏改底部 Tab（≤5 个）+ "更多"抽屉；分组规则仍适用但"固定底部"不适用
- **表单**：日期/级联用底部滚轮 picker；数字字段 `inputmode="numeric"`、验证码 `autocomplete="one-time-code"`；滑块热区 ≥44px；键盘弹出时聚焦字段保持可见（小程序 `adjust-position`）；问卷式逐条表单改"进下一题时校验上一题"
- **反馈**：Modal 改全屏页或半屏 Sheet；Drawer 改底部滑出 Sheet；Popconfirm 变居中轻量确认框（ActionSheet 只用于多选不用于确认）；Tooltip 几乎不用，改长按提示或首次引导气泡；触摸目标 ≥44px
